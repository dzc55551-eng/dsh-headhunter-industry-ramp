# 阶段 0 · 岗位锚定：把 JD 拆成能力画像

拿到陌生岗位，第一件事不是查行业，是拆 JD。JD 里已经藏了这个岗位 60% 的答案，只是用的是行业黑话。

## 一、技术栈指纹：从名词反推技术路线

把 JD 里所有"看不懂的名词"列出来，逐个查三件事：**是什么、属于哪一层、哪家公司在这上面强**。
这些名词的组合就是这家公司的技术路线指纹。

以人形机器人 / 具身智能为例（其它行业同理，换掉名词即可）：

| JD 里的词 | 实际含义 | 反推出什么 |
|---|---|---|
| VLA / 视觉-语言-动作模型 | 端到端多模态大模型控制机器人 | 走"大模型派"，要数据规模和多模态经验，人从自动驾驶/大模型团队来 |
| 强化学习 / Sim2Real / 域随机化 | 在仿真里训练再迁移到真机 | 走"仿真训练派"，要物理引擎与 sim2real 调参经验 |
| MPC / WBC 全身控制 / 零力矩点 | 传统模型控制方法 | 走"控制派"，要动力学建模功底，人从四足/工业机器人来 |
| 灵巧手 / 腱驱 / 力控 / 触觉 | 末端执行器与力反馈 | 硬件执行端，人从精密传动、医疗器械来 |
| 谐波减速器 / RV / 无框力矩电机 | 上游核心零部件 | 零部件公司，不是本体公司 |
| 遥操作 / 数据采集 | 人工示范采集训练数据 | 说明数据是瓶颈，这家公司还没跑通自动数据闭环 |

**关键判断**：一个 JD 同时要"VLA + 强化学习 + 传统控制"三种人，说明这家公司技术路线还没定，或者 HR 在堆关键词。这两种情况对猎头的意义完全不同——前者是高价值机会（路线之争中的人最贵），后者是需求不清晰（先别急着找人）。

## 二、硬性项 vs 加分项 vs 装饰项

| 类型 | 识别特征 | 处理 |
|---|---|---|
| 硬门槛 | 出现具体数字（5 年以上、带过 10 人团队）、"必须""要求" | 决定池子宽度，不可绕 |
| 真需求 | 排在 JD 前 3 条、全文重复出现、与业务痛点对应 | 这是搜寻主线 |
| 弹性项 | "优先""加分""熟悉…者更佳" | 用来做差异化排序 |
| 装饰项 | HR 抄模板的通用要求（"良好的沟通能力""熟悉 Office"） | 直接忽略 |

经验：JD 前 3 条基本是真需求。如果前 3 条全是软性描述而技术要求在后面，说明写 JD 的人不懂业务，得靠客户沟通补。

## 三、组织上下文

三个问题决定人选的层级和话语权：

1. **汇报给谁**——创始人 / CTO / 事业部总经理，完全不同。汇报给创始人意味着要能扛战略，汇报给事业部意味着要能扛交付。
2. **团队现状与目标**——0-1 建队还是 1-N 扩编？现在几个人，半年后要几个人？
3. **协作边界**——算法、硬件、产品怎么分工？这个岗位管到哪为止？

## 四、商业上下文

- 薪酬带宽与结构（现金 : 期权比例）
- HC 真实性与紧急度
- 客户心里的"完美画像"与"可接受画像"差多远

判断 HC 真实性的土办法：问"这个位置开放多久了""面过几个人""都卡在哪一步"。
开放 3 个月以上、面过 5 个人以上还空着，通常不是没人，是客户的画像本身有矛盾——这时候你的价值在于帮他改画像，而不是继续找人。

## 六、待确认清单（首次客户沟通必问 5 项）

1. 这个位置是新设还是补位？前任为什么走？
2. 最不能妥协的一条是什么？可以妥协的是哪几条？
3. 汇报给谁？团队现在几个人，半年内要扩到几个？
4. 薪酬的真实上限是多少？期权怎么算、行权条件是什么？
5. 之前面过的人卡在哪一步？

这五个问题问完，通常能省掉后面 30% 的无效搜寻。
