# 行业速研报告 · 文案骨架（配 HTML 主模板使用）

> 用法：报告以 `templates/report-template.html` 为主载体，本文件管**写什么**，模板管**长什么样**。
> 出 docx 时由同一份 HTML 转换，节序与结论一字不改。不要先写 Word 再另做网页，两份必然分叉。
> 每节标题写成结论句，不写"行业概况"这类分类名。客户扫目录就要能拿到判断。

---

## 封面

**标题**：{{公司名}} {{岗位名}}（{{城市}}）· {{报告主题}}

**一眼结论**（4-6 行，必须讲完四件事：这是什么岗 / 钱在哪 / 人在哪 / 难点在哪）：

> 这不是一个"{{通用岗位}}"，而是一个 **{{真实属性}}**——挂在 {{A}} 名下，实际干的活 {{比例}} 落在 {{B}} 上。
> {{薪资}} 只是<b>入场价</b>：{{真实带宽 + 依据}}；
> 真正匹配的人不在 {{表象行业}}，而在 **{{真实来源池}}** 里。
> 难点不是找不到人，是 **{{一句话点出筛选要害}}**。

**四个数字**（每个都是判断，不是凑数统计）：原始池 {{N}} 家 · 主攻池 {{M}} 家 · 真实带宽 {{X–Y}}K · 交付节奏 {{A–B}} 周

---

## 01 一页结论：真实需求藏在 JD 没写的地方

- `.lead` 一段：3-5 句，讲清"JD 只有几行，但叠上公司产品节奏后，岗位归属立刻清晰"，中间用一次 `<strong>` 强调核心判断。
- 左卡「四条判断」：岗位性质（扩编/预研、量产/0-1）、能力重心（具体到工艺或技术名词）、人才真实所在地（列 4-6 家）、最大成交风险（一流嫌什么、二流缺什么）。
- 右卡「三条情报差」：客户手上资料过期之处、数字被更新的地方、新增业务对候选人的意义。每条带来源标签。
- 底部长框（`.c-key`）：一句话点出"最该被质疑或最该被强调的地方"，并写清你的动作。

---

## 02 岗位锚定：把 JD 拆成能力画像

- 四列表：JD 原文 / 行业黑话翻译 / 反推出什么 / 筛人含义。**"筛人含义"这一列是整表的价值所在**，必须写"硬项还是加分项、谁会被卡掉"。
- 类型表：硬门槛（不可绕）· 真需求（搜寻主线）· 弹性项（做排序）· 装饰项（直接忽略）。真需求那一行要点出"哪一句才是客户的真心话"。
- 蓝框：影子 JD（同期在招同名岗、薪资差），解读 HC 真不真、画像定没定死。
- 组织上下文表：汇报关系 / 团队规模 / 协作边界 / 薪酬结构 / 工作节奏 / HC 真实性，每行带 ✅L1 或 ❓L4。
- 黄框：必须问客户的矛盾点，给出 2 条岔路及各自对应的人才池。

---

## 03 能力画像表：要什么人、从哪类公司来

五列表：维度 / JD 原文线索 / 推断 / 置信度 / 待确认。目标公司池那一行要给**反向修正**——客户按知名度分类，通常权重是错的，按"产品形态与工艺复杂度"重排。

底部长框（`.c-key`）：四档重排——高命中立即打 / 中命中备选 / 低命中不优先 / 看似相关但不碰。

---

## 04 行业格局：钱集中在哪一节

- `.lead` 先给结论：钱不在上游也不在下游，在 {{X}} 环节，因为它同时掌握 {{三件事}}；再补一句"这个环节的毛利被什么咬住，所以这个岗位才看起来普通、实际关键"。
- 产业链三层表：环节 / 代表企业 / 价值量与格局 / 与本岗位的关系。上游那行要回答"这群人是不是半成品人才"。
- 口径之争表：不同机构给的第一名不同，用 rowspan 合并"怎么用"列，写一段可直接照读的话术。这是最能证明"读过原始报告"的一段。
- 三张卡：营收结构换挡 / 该品类最吃这个工种（列 4-6 个具体环节）/ 所以岗位落点在某地。
- 蓝框：趋势三条，只写对候选人有用、能当谈资的，不写宏观愿景。

---

## 05 六模块知识地图

`.outline` 组件，六模块：产业链 / 产品 / 技术 / 企业 / 人才 / 趋势。

- 每模块 2-4 条二级，关键处再下沉一级（`.m3`）。
- 没有结论的地方标 `<span class="tbd">待补</span>`，那是下一轮入口，不是遗漏。
- 技术那一层必须明确标出"本岗位所在层"，否则地图和岗位脱节。

---

## 06 四家标杆：谁值得挖，谁挖不动

2 家老牌 + 2 家新锐，覆盖不同技术路线与商业化阶段。每家一个 `.eco` 卡：

- **产品**：卖什么给谁
- **技术**：与别人的区别，具体到工艺或算法，禁止"技术领先"
- **团队**：研发怎么分组、谁带、重心在哪（拿不到人数就标 ❓L4）
- **商业化**：交付量、客户、真量产还是小批量
- **最新动态**：近半年关键事件
- **`.for` 段（必须有）**：对我们这个岗位意味着什么 + 一句可执行打法

底部蓝框：客户的清单之外、命中率更高的人才富矿。

---

## 07 人才地图四张表

表 1 公司池：按"可得性 × 匹配度"重排，不按知名度。分 A/B/C/D 四层（rowspan 合并），匹配度 5 分标绿。D 层不是候选人池，是情报源。

表 2 团队层：公司 / 团队 / 负责人 / 技术方向 / 人数 / 汇报线 / 近期变动。负责人一律"待核 ❓"，并写明三条补齐路径（招聘页组织信息、专利共同发明人、候选人转介绍）。**这张表的价值就在于标出"该去补哪个空"。**

表 3 人才层：用 P1/P2 画像代号，不写真实姓名。每人四项分项得分：技术栈 40 + 项目阶段 30 + 动机 20 + 可触达 10。≥70 值得推，50-70 备选，<50 不浪费时间。

表 4 岗位信号：公司 / 在招岗位 / 首发时间 / 持续时长 / 推断与动作。同岗多个价位、在线数月，比任何行业报告都真实。

---

## 08 薪酬对标：挂牌价是入口价

- `.lead` 给狠话：照挂牌价找 {{画像}} 注定失败，因为那个价位对应的是另一档人。
- 对标表：本岗 JD / 同城同岗更高档 / 市场均值 / 本地天花板。年包要算出来，指出客户真实上限在哪。
- 双卡：对本地人选打钱（涨幅 + 必须提前说清的社保公积金等隐性项）；对外地人选打总账与生活方式（购买力换算 + 客户明确红线）。
- 黄框：别拿上市/期权当筹码。只说公开事实，激励细节待客户确认，不自己算、不承诺。

---

## 09 触达：话术与题库

- 三个 `.script` 块（深色，可直接照读）：技术痛点式（命中率最高）、行业事件式（数据必须真实）、职业阶段式（对 5 年以上的人用）。每块下面一行灰色小字写"作用"。
- 痛点提问表：行业痛点 / 候选人版问题 / 听什么（真做过 vs 没做过）。**"听什么"列要给出两者的具体区别**，否则等于没写。
- 客户五问执行版：客户要求 / 电话里怎么问（可照读）/ 判据与一票否决线。
- 橙框第 6 问：客户没写但决定单子成败的那一问，解释它为什么比前五问加起来都值钱。
- 动机分型表：识别特征 / 切入角度 / 千万不要说。
- 三卡面试题库：技术判断类 / 落地验证类 / 协作与动机类，每类 5 题，可直接交给客户 HR。

---

## 10 搜寻路径与风险

- `.steps` 三周节奏：第 1 周打最短路径两条（本地 + 一个外地大池），第 2 周上高价值池并回报客户、抛岔路口问题，第 3-4 周定向挖（专利共同发明人、供应商圈、转介绍）。
- 三条建议表：动词开头的可执行建议 + 理由（带数据）。
- 待核验表：条目 / 当前状态 / 怎么补。"怎么补"必须具体到问谁、查什么、用什么反推。
- 红框：三条合规红线（不打听未公开数据、不诱导带资料、竞业只提醒不规避）。
- `.checklist` 交付前自检：6 条，每条后面直接跟答案，不留空问号。

---

## 11 来源与置信度说明

分级表四行（✅L1 / 🟡L2 / 🔵L3 / ❓L4），每行写清本报告哪些具体数据用它。L4 那行注明"全部标注，不进结论"。

方法论复盘蓝框：三句话讲清这次能出结论靠什么（先拆 JD、反向修正公司池、从招聘信号反推处境）。

页脚：报告名 / 编制 / 方法论 / 数据截止 / L4 免责声明 / 人才信息仅用代号 / **延伸资源链接**。

页脚**不写资料来源清单**。知识库名称只出现在页脚末尾标题为「延伸资源」的那一个链接区块里，不进正文、不进第 11 节分级表。来源只在本节的 L1–L4 表里按"类型"表达（官方公告 / 机构研报 / 行业媒体 / 待核验），不写"资料来自哪个库"。
